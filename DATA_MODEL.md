# Data Model

## Source data: `palestine-directory-research-data.json`

The raw research import file. Do not edit.

```
formatVersion: string
title: string
researchSnapshotDate: string      # When research was compiled (not a statement date)
packagedOn: string
reviewStatus: string
manifest:
  artistEntryCount: 919
  evidenceRecordCount: 1043
  registerEntryCount: 8932
evidenceTupleFields: [type, summary, sourceUrl, sourceLabel]
categoryDefinitions:
  G-D: "Direct anti-genocide statement"
  G-C: "Collective anti-genocide statement or boycott"
  S:   "Broader solidarity or ceasefire advocacy"
  H:   "Historical-only solidarity in the evidence collected"
limitations: string[]
campaignStatementSources: [{ campaign, url }]
artistIndex: [{ name, evidence: [[type, summary, sourceUrl, sourceLabel]], tier }]
registers: [{ id, name, sourceUrl, entryCount, entries: [string] }]
```

## Canonical records (internal)

### Artist

```
id:              string  # Stable hash of lowercased name
slug:            string  # URL-safe slug from name
name:            string  # Original name from research data
sortKey:         string  # Lowercased name with articles stripped
tier:            "G-D" | "G-C" | "S" | "H"
evidence:        Evidence[]
campaignIds:     CampaignId[]
status:          "draft" | "published" | "withdrawn"
reviewedAt:      string | null  # ISO datetime, null until reviewed
reviewedBy:      string | null
reviewNotes:     string | null
importedAt:      string  # ISO datetime
updatedAt:       string  # ISO datetime
```

### Evidence

```
id:           string  # Stable hash of artist + content
category:     "G-D" | "G-C" | "S" | "H"
summary:      string  # Exact text from research data
sourceUrl:    string  # Direct link to source
sourceLabel:  string  # Source publication/label
campaignIds:  CampaignId[]  # Derived from sourceUrl
```

### Campaign

```
id:           "nmg" | "mfp" | "euro" | "a4c" | "other"
name:         string
slug:         string
sourceUrl:    string
description:  string
registerId:   string | null
artistCount:  number  # Count of published artists in this campaign
```

## Campaign URL mapping

| URL pattern | Campaign ID |
|---|---|
| `nomusicforgenocide.org/page-3` | `nmg` |
| `nomusicforgenocide.org/eurovision` | `euro` |
| `nomusicforgenocide.org/` (homepage) | `nmg` |
| `musiciansforpalestine.net` | `mfp` |
| `artists4ceasefire.org` | `a4c` |
| Any other URL | `other` |

URLs can map to multiple campaigns (e.g., a URL containing "eurovision" maps to both `euro` and potentially `nmg`).

## Publication states

```
draft      → Imported but not yet reviewed or published
published  → Reviewed and visible in public output
withdrawn  → Was published, now removed from public output
```

State transitions:
- `draft` → `published`: requires review first (publication safeguard)
- `published` → `withdrawn`: via `npm run withdraw`
- `withdrawn` → `published`: via `npm run publish` (review still required)
- Any → `draft`: not directly supported; use `--unreview` to clear review state

## Registers (reference only)

The three registers contain 8,932 raw entries that are **not** published as artist profiles. They are reference data used to understand campaign scope. Only the 919 curated artist index entries become profiles.

## Public export

Generated by `npm run build:data`. Contains only published artists.

```
generatedAt:           string
researchSnapshotDate:  string
categoryDefinitions:   Record<string, string>
limitations:           string[]
campaigns:             Campaign[]
artists:               CanonicalArtist[]  # Only published
searchIndex: [{ id, slug, name, sortKey, tier, campaignIds, evidenceCategories, evidenceCount }]
stats:
  totalArtists:        number
  publishedArtists:    number
  totalEvidence:       number
  byCategory:          Record<string, number>
  byCampaign:          Record<string, number>
```

The search index is a compact subset of artist data for client-side search. Full artist records (with evidence details) are also included for profile pages.

## Zod validation

All data structures are validated with Zod schemas defined in `src/lib/schemas.ts`. Validation occurs:

1. **At import time**: Raw research data validated against `researchDataSchema`
2. **At export time**: Public export validated against `publicExportSchema`
3. **At write time**: Canonical artists validated against `canonicalArtistSchema` when saved to the store
4. **At test time**: Unit tests verify schema validation catches invalid data
