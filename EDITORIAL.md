# Editorial Guide

## Workflow

### 1. Import

```bash
npm run import
```

Reads `src/data/palestine-directory-research-data.json`, validates it against Zod schemas, and transforms it into canonical artist records stored in `src/data/editorial/artists.json`.

The import is **idempotent**: running it again preserves existing review and publication state. New artists are added as drafts.

Use `--dry-run` to validate without saving:

```bash
npm run import -- --dry-run
```

### 2. Review

Before an artist can be published, an editor must review it:

```bash
npm run review -- <slug> --reviewer "editor-name" [--notes "optional notes"]
```

Review verifies:
- Source links are accessible and support the claimed evidence
- The artist's identity is correctly attributed
- Campaign associations are accurate
- Evidence summaries match the source content
- No quotations are invented or altered

To clear a review (revert to unreviewed):

```bash
npm run review -- <slug> --reviewer "editor-name" --unreview
```

### 3. Publish

Only reviewed artists can be published:

```bash
npm run publish -- <slug>
```

If the artist hasn't been reviewed, the command will refuse and tell you to review first.

To publish all reviewed-but-unpublished artists at once:

```bash
npm run publish -- --all-reviewed
```

### 4. Withdraw

To remove a published artist from the public output:

```bash
npm run withdraw -- <slug>
```

The artist remains in the editorial store with `withdrawn` status and can be re-published later.

### 5. Build export

After publishing or withdrawing, rebuild the public export:

```bash
npm run build:data
```

This generates `src/data/public-export.json` containing only published artists.

### 6. Build site

```bash
npm run build
```

Builds the static Astro site and verifies the export contains no drafts.

### 7. Validate

Run the full validation suite:

```bash
npm run validate
```

Checks:
- All artists pass Zod schema validation
- All published artists have been reviewed
- All slugs are unique
- All evidence records have campaign IDs
- Public export is consistent with the editorial store

### 8. Status

Check the current state:

```bash
npm run status
```

Shows total/draft/published/withdrawn counts and the last 10 audit log entries.

## Publication safeguards

1. **Review gate**: The `publish` command refuses to publish unreviewed artists
2. **Export filter**: `buildPublicExport()` only includes artists with `status === 'published'`
3. **Verification**: `npm run verify:export` runs after every build and checks for draft leakage
4. **Unit tests**: `tests/unit/leakage.test.ts` verifies drafts, withdrawn, and unreviewed artists never appear in exports
5. **Schema validation**: Every artist record is validated with Zod on write and on read

## Audit log

All editorial actions (import, review, publish, withdraw, unreview) are logged to `src/data/editorial/log.json` with timestamp, actor, artist IDs, and optional notes. This log is displayed on the `/changes` page.

## What not to do

- **Do not invent quotations.** Evidence summaries must come from the source data.
- **Do not invent review dates.** Review timestamps are set automatically when `npm run review` is run.
- **Do not invent artist information.** The directory only contains what's in the research data.
- **Do not publish without review.** The publication safeguard prevents this.
- **Do not edit the raw research data file.** It is the source of truth for evidence.
- **Do not edit `public-export.json` directly.** It is generated by `npm run build:data`.
